# Служба технической поддержки

Настольное приложение для приёма обращений и автоматического назначения оператора. Это не сайт: окно программы на GTK 4 и libadwaita, данные лежат в SQLite.

## Запуск

Нужны Python 3, GTK 4 и libadwaita. На Omarchy они уже стоят, отдельные пакеты ставить не нужно.

Из корня проекта:

```bash
python main.py
```

То же самое: `python -m evelina`.

Готовая программа без исходников собирается так:

```bash
python -m venv --system-site-packages .venv
.venv/bin/pip install pyinstaller
.venv/bin/pyinstaller --noconfirm evelina.spec
```

Файл запуска: `dist/evelina/evelina`. Это программа для Linux. Рядом с ней, в `dist/evelina/data/`, лежит её база. Файл `.exe` для Windows эта сборка не делает: окно завязано на GTK этой системы.

При первом запуске создаётся `data/support.db` и наполняется тестовыми учётными записями и обращениями. Повторный запуск эти строки не дублирует.

## Вход

| Кто | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `admin` |
| Операторы | `ivanov`, `petrova`, `sidorov`, `kozlova`, `orlova` | `operator` |
| Пользователи | `smirnov`, `volkova`, `morozov` | `user` |

Регистрация в окне входа создаёт только пользователя. Роль оператора или администратора назначает администратор.

Специализации операторов: Иванов — оборудование, Петрова — программы, Сидоров — сеть, Орлова — доступ, Козлова — прочее (универсальный оператор).

## Роли

**Пользователь** создаёт обращение и видит только свои. Может писать комментарии и вернуть решённую заявку в работу.

**Оператор** видит свободные обращения и свою очередь. Свободную заявку можно взять. По своим заявкам меняет статус: в работу, решено, закрыто.

**Администратор** видит сводку, всех пользователей и все обращения. Меняет роль, специализацию и активность. Назначает оператора вручную или запускает распределение. Отключение оператора возвращает его открытые заявки в очередь.

## Как назначается оператор

У каждого активного оператора считается балл:

- совпала специализация с категорией обращения: +40;
- универсальный оператор (специализация «прочее»): +12;
- за каждую заявку в работе снимаются баллы, и чем выше приоритет, тем штраф больше;
- оператор с пятью и более активными заявками не выбирается, пока есть кто-то ниже этого предела. Если на пределе все, берётся наименее загруженный.

В карточке после автоматического назначения видно, почему выбран именно этот оператор.

## Структура

```
main.py                 запуск из исходников
evelina.spec            сборка программы
evelina/
  __init__.py
  __main__.py           python -m evelina
  db.py                 SQLite: пользователи, обращения, комментарии, журнал
  distribution.py       выбор оператора
  ui.py                 окно, вход и панели ролей
data/
  support.db            база, создаётся при запуске
```

## База

Файл `data/support.db`.

- `users` — одна таблица учётных записей. Роль хранится в поле `role`: `admin`, `operator`, `user`. Логин уникален.
- `tickets` — обращения. Автор и оператор ссылаются на `users`.
- `comments` — переписка по обращению.
- `history` — журнал действий: создание, назначение, смена статуса.

Открытое обращение с той же темой у того же автора второй раз не создаётся. Пароли хранятся как хеш, не открытым текстом.
